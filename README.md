# Corkboard

A local whiteboard for PDF snippets. You read and snip in one view, then sort and link the snippets on a board in the other view.

## Start

```bash
npm install
npm start
```

`npm start` opens http://localhost:4747 in your browser. `npm run serve` starts the server and does not open a browser. All data stays in `./data` (boards, PDFs, snippets, images). A deleted board goes to `data/trash`.

## Use

- **Projects**: the first view. Each project holds its own boards and PDFs, and shows a preview of its newest board. New PDFs go into the open project. "＋ Add" → "From the library" shares PDFs between projects: it shows the global folders with every PDF of the library. Tick files, or a folder for all the files in it, then Add. Deleting a project moves it and its boards to `data/trash`. Its PDFs stay in the library, unless you tick the box to also trash the PDFs that only this project uses. A board in no project becomes a project of its own (this is how the boards from before projects got their projects).
- **Review projects**: the reverse of a board. In the Projects view, click ＋ New review, name it, and add the PDF to check (a test plan, a new report). Mark its passages in the reader, and link each one to snippets you already have in other PDFs: the link list opens on "Every PDF in the library" and searches them all at once. The reader's Links tab lists every passage in page order with the snippets it links to (in their paragraphs), Open and Unlink buttons, and ＋ Link for passages with no link yet (a tick box shows only those). A review has no board, so the Board view is hidden for it.
- **Library** and **Board library**: tabs in the Projects view. The library holds every source: PDFs, snapshots of web pages, files, and docs that you write. "＋ Add" there adds a source to the library, in no project. The library is the global folder browser: the global folders with every PDF, each with its snippet count and its projects. Click a PDF to open it by itself, outside any project, to read it and to make snippets. Click a folder to close or open it. Drag a file or a folder onto a folder to move it. Right-click a PDF: open, open in one of its projects, add to a project, rename, new folder, move, delete. Right-click a folder: new folder in it, rename, move, delete, snapshot again. Right-click the empty area: new folder, or a snapshot of a folder on the disk. The filter in the top bar shows the files that match. The board library lists every board: open, move to another project, or move to the trash.
- **Pictures across pages**: a text selection that crosses a page, snipped as a picture (📷 Picture, or "Add picture" on a text snippet), gives one picture: the part on each page, one under the other, with no space between. With "Skip headers and footers" on, the footer and header between the pages are left out. "Adjust picture" on such a picture shows one box for each area: change each box by itself (its height, its width, its place), or take an area out with "Remove area", then Done.
- **Sections list**: the Sections tab has a search field and sections that close. Click the arrow of a section to close or open its sub-sections. "Close all" and "Open all" do it for every section. A search shows each match with its parent sections. The closed sections are kept for each PDF.
- **Dictionary**: terms and their definitions, in two scopes: the project and global. Each use of a term has a dotted underline, in the reader and on cards. Point at it for the definition, with a link to the passage that defines it.
  - **From a document**: when a PDF of a project opens for the first time, Corkboard looks for a section called Definitions, Terms or Terminology (also Glossary, Abbreviations, Acronyms). It reads the entries (a two-column table, numbered entries, or "term: definition" lines) and shows them in a review list before they go in. The list shows each term with its full definition and its page, with a filter and a count of the ticked entries. Click the text of an entry to correct it. Notes and examples stay in the definition of their term, and page headers, footers and download notices are left out. "Find the terms section of this PDF" in the Terms tab does it again.
  - **By hand**: "＋ Add" in the Terms tab of the reader or in Options → Dictionary. Or select text in a PDF and click "📖 Define term": a short selection is the term, a long one is the definition.
  - **Matching**: whole words and full terms only. A capital-letter term (HAC) matches with those capitals only. Where two entries define one term, the open document's own entry wins, then the project's, then the global one.
  - The terms are in `data/terms` (one file per project, and `global.json`).
- **Selecting text in the reader**: a drag does not have to stay on the letters. Past the end of a line (for example past a full stop), in the gap between lines, or from the margin, the selection goes to the nearest letter of the nearest line.
- **Sidebar widths**: in the reader, drag the line between the PDF and a sidebar (the Files panel at the left, the Snippets / Sections / Details / Terms panel at the right) to change its width. Double-click the line for the standard width. The PDF keeps 320 px at least. Corkboard remembers the widths.
- **Files panel**: "▤ Files" in the top bar of the reader opens a panel with the sources of the project in folders. "＋ Folder" makes a folder. Drag a file or a folder onto a folder to move it, or onto the panel to move it to the top. Right-click a folder: new folder in it, rename, move, delete (its files go one level up). Right-click a file: open, open in a new tab, rename, new folder, move to a folder. Right-click the empty part of the panel: new folder. Click a folder to close or open it, and a file to open it. The filter shows the files that match, with their folders. The folders are in the project only: nothing moves on the disk, and another project can file the same PDF in another way. The panel has two sets of folders, as the dictionary has two scopes: **Project** (the folders of this project, for its own PDFs) and **Global** (one set of folders for every PDF in the library, the same in every project and in the library). In the global folders, a PDF that is not in the open project shows grey: right-click it for "＋ Add to this project". The global folders are in `data/files.json`. **Snapshot of a folder on the disk** (global folders, desktop app): right-click the empty part of the panel → "⤓ Snapshot a folder from the disk…" and pick the folder. Corkboard copies every PDF in it (and in its folders) into the library and makes the same folders in the global set. It is a copy at that moment, not a live link: nothing on the disk changes. Right-click the top folder of a snapshot → "↻ Snapshot again" to take what is new. A PDF that you moved to a folder of your own stays there, and a PDF that left the disk stays in the library. Files that are not PDFs are left out.
- **Reader tabs**: a tab strip above the PDF. "＋" makes a second tab of the same PDF at the same place: scroll it to another section, or pick another PDF from the PDF list to show that one in the tab. Each tab keeps its place and zoom. A card's source button or a link goes to the tab that already shows that PDF. Close a tab with × or a middle click. Ctrl+Tab and Ctrl+Shift+Tab go to the next and the previous tab. Tabs are kept per project.
- **Middle-button autoscroll**: click the middle mouse button on the PDF, a list or the board, then move the pointer away from the anchor. The view moves that way, faster with distance. The next click, Esc or the wheel stops it. Hold the button and move to scroll only while it is held (on the board, a middle-button drag still pans).
- **Theme**: Options → Theme: "Same as the computer" (the default), Light or Dark. The choice stays in this browser, and other windows follow it. In the dark theme, PDF pages and pictures stay white, and near-black ink and arrows show light (the stored colours do not change).
- **Removing a PDF**: open it in the reader and click "✕ Remove" next to "＋ Add". The PDF leaves the project and stays in the library. Tick the box to delete it instead: the PDF and its snippets go to `data/trash`, and it leaves every project. In the library on its own, Remove always moves the PDF to the trash. Cards already on boards stay.
- **Read**: select text, or use **Area** for figures and tables, and pick a colour. Write a note in the box that opens.
- **Layers and links**: a snippet inside another snippet (a term in a paragraph) is a layer: it shows underlined, a click picks the innermost one, and its menu opens the outer one. "↗ Link to…" links a snippet to another (labels: defined by, refers to, see also), from a searchable list or by a click in the PDF. Links can point into other PDFs (a PDF selector in the link list) or at a whole document. Linked terms show ↗ and a hover tip. Go opens the other PDF at the target, and ← Back returns. A definition lists the terms in other PDFs that link to it. Cards list their links: a click goes to the target card or places it beside the card, and PDF opens it in the reader. Placing a snippet on a board adds arrows to the cards of its linked and layered snippets.
- **Sub-links**: a card shows the snippets inside its snippet as highlighted words, in their own colours. A link between two inner snippets (for example "may" in a requirement and "may" in a definitions paragraph) draws an arrow from the highlighted word on one card to the highlighted word on the other. The arrow is drawn when you place a card, or when you make the link while both cards are on the board. An arrow from (or to) a highlighted word takes that word's colour, until you pick a colour for the arrow. Hover a highlighted word to light its arrow and the word at the other end. Click a linked word, or a link in a card's link list, to open a popup with the target: a highlighted word shows inside its paragraph. The target does not have to be on the board. The popup has Open in PDF, and ＋ Place on board (or Go to card when it is there already). The popup also lists the links that point into a highlighted word (from this project's PDFs and from other PDFs in the library), each shown in its paragraph with Open in PDF and Place on board. A word with no links either way goes along its arrow. The card's link list shows these links as “word” label: target. The tray treats a highlighted word inside a card on the board as on the board, so it hides it with "Hide snippets already on this board".
- **Highlighting on the board**: pick the Highlight tool (H) and select words in a card's text, then pick a colour. The highlight stays on the card only: it does not go back to the PDF. Click a highlight (with the Highlight tool) to change its colour, remove it, or "↗ Link to a word or card": then click a highlighted word or a card, and a word-to-word arrow appears (in the highlight's colour). On a picture card, drag a box with the Highlight tool to highlight part of the picture. A box has the same menu: colour, link, remove. Highlights made in the reader still show on their cards as highlighted words too. To take such highlights out of the PDF and keep them on the card only, use one of these: "Only on this card" in the highlight's menu, "⇣ Its highlights only on this card" in a card's right-click menu, or Options → "Highlights only on the cards…" for the whole board. Each highlight keeps its colour and its arrows. A highlight that is also a card of its own on the board stays in the PDF.
- **Find**: in the reader, press ⌘F (or Find in the side rail) and type. Every match on every page is marked (on a page whose text is drawn, the marks come from the drawn letters, so they sit on the words), and the view moves to the first one at or after where you are. Enter or ↓ goes to the next match, ⇧Enter or ↑ to the one before. Esc closes the bar. Case and spacing do not matter, and a phrase can run over a line end.
- **Reference tags**: select a citation, a "see §…" or a document name and click 🔖 Reference in the menu. It becomes a snippet in the reference colour (teal, with a solid underline), and the link list opens so you can link it into another PDF, to a snippet, or to a whole document. An existing snippet's menu has 🔖 Reference / Not a reference. Lists show a "reference" badge, cards show REF, and highlighted words that are references show teal.
- **Headers and footers**: a snippet that crosses a page leaves out the page's running header and footer. Corkboard finds them by itself: lines near the top or bottom that repeat on many pages (page numbers count as the same). To mark one by hand, select it and click "Skip as header/footer": text at that height is then skipped on every page. The Details tab shows what was found and can forget the areas marked by hand. Options → Skip headers and footers in snippets turns this off. Page numbers that the reader draws under each page are never part of a selection.
- **Sections**: select a heading and pick Section, Sub-section or Level 3, or use "＋ Section at this page" in the Sections tab. A PDF with its own bookmarks can import them. A PDF with a contents page shows "Sections from the contents page (N)" in an empty Sections tab: one click makes a section for each entry, at the place where its heading starts in the text. Levels come from the numbers (4.2.1 is level 3), or from the indent. Corkboard finds the difference between the printed page numbers and the pages of the file. A heading that it does not find starts at the top of its page. Snippets, the tray and cards show the section path, and the tray can filter by section.
- **Add sources** (＋ Add): one dialog with four tabs. Files: PDFs, and images, HTML, text and Markdown files, which are saved as PDFs. Web page: paste an address, and the page is opened in a hidden window and saved as a PDF snapshot (with its address and the date, shown in the Details tab). New doc: a source that you write (see Docs). From the library: sources you already have. A snapshot works like any PDF: snippets, sections, links, find. Web pages and non-PDF files need the desktop app (Electron); in a plain browser only PDFs can be added.
- **Docs**: a doc is a source that you write in Corkboard, as you write a note card. ＋ Add → New doc (or right-click the empty part of the library or of the Files panel → "＋ New doc"), give it a name, and write. The editor is the same as in a note card: headings, lists, tables, equations. "Done" saves the doc. Then the reader shows it as pages, and you snip, link and place it on a board like every source. "✎ Edit" in the top bar of the reader (or right-click the doc → "✎ Edit the doc") opens the editor again. After a change, Corkboard finds each snippet and section of the doc again by its words, so they move with the text. A snippet whose words you removed keeps its old place and shows "⚠ not in the doc now". While you write, the text is saved as a draft. Docs need the desktop app. The document is in `data/docs`, and the library has the PDF that Corkboard makes from it.
- **Standalone PDFs**: a click on a PDF in the library opens it with no project. Sections, snippets, notes and the Details tab (title, description) belong to the PDF, so they come with it into every project.
- **Picture snippets**: the selection menu has Text | 📷 Picture. Picture snips the selected area as an image and keeps the text. A text snippet's menu has 📷 Add picture / Remove picture. ⤢ Adjust picture shows the picture's box on the page with handles: resize or move it, then Done (Enter) snips the new area, Reset returns to the box around the text, Cancel (Esc) changes nothing. Cards and lists show the picture with the text below.
- **Notes**: right-click the empty board for a menu: Add custom card, or Add a zone here (N or the Card button also make a card). A new card stays even when you leave it with no text. Right-click a card for its menu: write in it, open it in its PDF, or delete it. Double-click a note to write in it. A note is a small document: you see the format while you type. The tool bar over the note has bold, italic, underline, strike through, superscript, subscript, three headings, lists, tasks, quotes, alignment, links, text colours, highlights, tables, equations and three text sizes. Standard keys work (⌘B, ⌘I, ⌘U, ⌘K, ⌘. for superscript, ⌘, for subscript, Tab in a list or a table). You can also type the marks: `# ` heading, `- ` list, `1. ` numbered list, `[ ] ` task, `> ` quote, `$x^2$` equation. **Tables**: the ▦ button makes a table of 3 by 3. Right-click a cell to add or delete rows and columns, to make a header row, or to delete the table. **Equations**: the ∑ button opens a small window for LaTeX, with a preview. Click an equation to change it. Click a task's box to tick it. Web links in a note open in the browser. A note from before this editor stays as it is until you change it. The editor is a separate library (`~/Projects/docedit`). Corkboard has a built copy in `public/vendor/docedit`. After a change to the library, run `node build.mjs ../Corkboard/public/vendor/docedit` in the library folder.
- **Zones**: pick Zone (Z) in the side rail and drag a box on the empty board. A zone is a group: cards whose middle is inside it belong to it and move with it. After you draw a zone, a box asks for its name. Click ✎ or double-click the title to rename it later, click the dot to change its colour, drag the corner to resize, × removes the zone only.
- **Footnotes**: a snippet that holds a footnote mark (a small raised number, or * † ‡ §) carries that footnote's text from the foot of its page. Cards, lists and the preview show it under the snippet. ↻ Refresh text (or Refresh all in the Details tab) adds footnotes to older snippets.
- **Groups**: Options → Group by document puts each PDF's cards in a labelled frame, in document order (other cards get an "Other cards" frame). Options → New group adds an empty frame. Drag a frame's title bar to move it with its cards, drag its corner to resize, double-click the title to rename, × removes the frame only. A card belongs to a frame while its centre is inside it. The tray shows a heading per PDF.
- **Snippet formatting**: a text snippet keeps its line breaks. List items (a), b), 1., i., •) and lines after a colon start new lines. Each new line keeps its indent level from the page (a sub-item such as i. under a) shows one level deeper, and the items of one list, such as a) b) c), always share a level), and list items get a hanging indent on cards, in lists and in the preview. A snippet that starts inside a line takes the indent of that whole line. Wrapped lines of a paragraph join, and a word split by a hyphen at a line end joins again. A line ends its paragraph only when the next line's first word would have fit on it, measured against the widest line of that paragraph, so lines in a narrow column stay together. "↻ Refresh text" in a snippet's menu, or "↻ Refresh the text of all snippets" in the Details tab, puts the line breaks and indents back into older snippets. A refresh keeps the words of a text snippet. It re-reads an area snippet's box only from the snippet's own menu.
- **Right-click menus**: on the board, right-click for what you can do there. Empty board: Add custom card, Add a zone here. A card: write in it, colour (notes), open in its PDF, fit the height, delete. A connection: its bar opens where you clicked, with the label, note, direction, colour, line style, width and delete. A zone (its title bar or an empty spot inside it): rename, colour, remove. A left click on a connection only selects it; Enter or a double-click on its label also opens its bar.
- **Highlight mode**: in the reader, pick Highlight in the side rail and a colour under it. Every text you select is coloured at once, with no menu. These highlights are not snippets: they do not show in the snippet lists, the tray, the board or the link list. Click one to change its colour, make it a snippet, or delete it.
- **Watching the sources**: each source (a PDF, or the snapshot of a web page) has a status in its Details tab: Not set, Current, Superseded or Withdrawn, with a note. You set it. A source also has an address to check: a web snapshot has its own, and for a PDF you paste the address of the page that shows its status (the catalogue page of a standard).
  - **The check** loads the address and reads the status that the page declares ("Status: Inactive-Withdrawn"). When that is not the status you set, Corkboard offers it: it never changes the status by itself. For a web page ("What to check": the status and the text of each snippet), it also looks if the text of each snippet is still on the page. A snippet whose text is gone gets the mark "⚠ changed at source", and you can save a new snapshot of the page.
  - **When**: when you open a project, for each source that was not checked in the last 30 days. Also "Check now" in the Details tab, and "Check all now" in Options → Sources, which lists every source of the project with its status and its last check.
  - **Marks**: the snippets and the cards of a source that is withdrawn or superseded show "⚠ withdrawn" or "⚠ superseded".
  - **Sign-in**: "Sign in to this site…" opens the address in a window, where you sign in yourself. Corkboard keeps that web session (not your password) for later checks and snapshots.
  - The check needs the desktop app and the network. It contacts only the addresses of your sources.
- **Duplicate card**: right-click a card → "⧉ Duplicate card". The copy is a separate card with the same content, next to the first one, with no arrows: draw the arrows of its own path. Use it for a card that has a place in two paths at different points. Each card of a snippet shows a mark such as "⧉ 1/2": click it to go to the next copy. A change of the snippet in the reader shows on every copy. A note card can be copied too.
- **Guides**: while you move a card, it goes in line with other cards: its left edge, middle or right edge to the same of another card, and its top, middle or bottom too. A pink line shows what it is in line with. While you change the size of a card, its edge goes in line with an edge of another card, or the card gets the width or height of another card: a green bar then shows along each card of that size. The reach is about 7 px on the screen. Hold Alt to move or size freely. Options → "Guides" turns them off. Guides do not work while gravity is on.
- **Choices (one branch at a time)**: for a split in a document ("try A, if that fails try B, then C…"). Right-click the card with the split and click "⑂ Make this a choice". The cards that its arrows point to are the options. The card gets one button for each option, and All. Click an option (its button, or the option card): the board shows only the cards that follow from that option. The cards of the other branches go off the board, so the branches can use the same space. These always stay: the option cards, the cards before the choice, and a card that another shown card leads to as well. All shows every branch with see-through cards, so you can see where they lie on each other. A branch can have a choice of its own. An arrow from a branch back to a card before the choice ("see clause 5") does not count for the branches. The selected option is saved with the board, and "Find on board" shows the branch of the card that it goes to.
  - **Paths that share cards and then go different ways**: the colours of the arrows tell the paths apart. Give the arrow that brings path A to the shared card a colour (right-click the arrow), and give the arrow that continues path A after it the same colour. Do the same for path B with another colour. A path keeps the colour of the last arrow on it that has one, so the shared cards can be a run of cards. A path does not follow an arrow that has the colour of another path at that card. An arrow with no colour of its own, or with a colour that no other path has there, is part of every path that comes to it. The colour of the arrow from the choice card to an option is the first colour of that option (its button shows it). Only a colour that you set on the arrow counts: a colour that an arrow takes from a highlighted word does not.
- **Connections**: arrow ends slide along the card sides that face each other. Where those sides overlap, the arrow runs straight across. Two or more arrows that leave one card with the same label start from one point, and the label shows once there with a count (for example “cover cites ×4”). Arrows from highlighted words keep their own start. Arrows with the same label that start near each other and end near each other run as one trunk in the middle, with one “label ×N” tag, and split apart near their cards (curved arrows only). Arrows go around other cards: a curved arrow that would cross a card bends past it (and enters a card by the side that faces its last bend, so it does not hook round), a trunk that would cross a card moves sideways, and circuit arrows pick the straight-run route that crosses no card. Circuit arrows of a trunk share one middle run (a bus). Click an arrow to open the connection bar. Enter on a selected arrow goes to its label. Set a label, a note (shown on hover), the direction (→ ← ↔ or none), the colour (8 colours), the line style (solid, dashed, dotted, dash-dot, double, track, glow), the width (thin, normal, bold), or delete the arrow. Old dashed arrows show as Dashed. Near a card, an arrow takes the direct way in: where a bend is already next to the card, the arrow goes from the bend straight to the card (at an angle), with no hook. An arrow of a same-label group whose target is behind the group's start point starts on its own. The side that an arrow end uses is a balance: how far apart the two cards are in that direction (the gap between their edges), and how much free space is in front of the side. A side with another card close in front of it counts for less, so an arrow that can enter by the top or by the left takes the one with free space. Where an arrow must bend round another card to reach its card, it enters by the side that the bend is next to, if that side has more free space (it does not push into a small gap between two cards). An arrow end stays 48 px from a corner of a card (about a third of the side on a short card), so the arrow has room to turn in. The arrow ends on one side of a card are in the order of where their arrows go (the arrow to the card further down leaves further down), with a small space between them, so the arrows of one card do not cross each other at the card. For this, an end can go nearer to a corner (14 px). Arrows with the same label that start at one point show the label once, with no count, at the middle of the longest of them. A label does not sit on a short arrow: it goes beside the arrow, or the short arrow goes without it when another arrow from the same card shows that label. You can drag a label along its arrow: the label goes to the place on the arrow that is nearest to the pointer, and it stays on the arrow. It keeps that place as a part of the arrow's length, so it stays there when the cards move. Drag it to a side of the arrow and it goes with the pointer, as far as just off that side (where it does not cover the line) and no further. Let it go on the line near the middle and it sits by itself again. A double-click on a label still edits its text.
- **Tray preview**: click a tray snippet. Its card comes to the centre, or a preview opens in the middle of the board with ＋ Place on board and Open in PDF. ←/→ step through the tray.
- **Board**: drag snippets from the tray onto the board. Drag a card's edge dot onto another card to connect them. Click "↗ file · p.N" or the PDF button on a card to open its source in the reader.
- **Resize cards**: drag a card's corner grip (width and height), its right edge (width) or its bottom edge (height). Long text scrolls inside a short card. Double-click the corner grip to fit the height to the text again. A picture card keeps the shape of its picture, so only its width changes.
- **Pen and Erase**: draw anywhere on the board. A stroke that starts on a picture stays on the picture, a stroke that starts on a card moves with that card, and a stroke that starts on the empty board stays on the board. Erase removes strokes under the pointer (old marker strokes too). Hold Shift for a straight line. The connection dots hide while these tools are on.
- **Travel**: double-click an arrow. The view moves to the card at the other end.
- **Focus**: select a card and press 1, 2 or 3. Only the cards within that many links stay visible. Press 0 or Esc to show all.
- **Structured layout**: press L. Each group gets a lane: the card's `group`, else its colour. The busiest lane follows document order (PDF, page, place on page). Other lanes line up with the cards they link to. Header cards (`laneHeader: true`) stay on top, and their position sets the lane order.
- **Export**: Options → Export writes one self-contained HTML file, with or without the source PDFs. A copy goes to `data/exports/` and is served at `/files/exports/`. The file has its own viewer: pan, zoom, search (Enter goes to the next match), focus on a card, and travel along an arrow. **Choices** work in the file: it holds every view that the choice buttons can make, with the arrows of each view, and a click on an option button or an option card shows that branch. A board with too many combinations (more than 400 views) gives a file with a part of them, and the status line says so. A link in the list of a card goes to its card (and shows its branch), or opens the PDF. A click on a highlighted word goes to the word at the other end of its arrow. A term of the dictionary shows its definition when the pointer is on it. The file keeps the theme (light or dark) that the app had at the export. Note cards keep their format, tables and equations.
- **Circuit arrows**: Options → Arrows → Circuit. Arrows use straight lines with 90° turns.
- **Options**: rename, delete, arrow style, layout, the snippet tray and New window are in the Options menu.
- **Gravity**: press G. Linked cards pull together, cards push apart, and cards of the same colour gather. Undo returns the layout from before.
- **Two screens**: Options → open the other view in a new window. The two windows stay in sync. If a window holds an old copy of a board, the server refuses its save and the window reloads the board. A window cannot re-create a deleted board.

## Install with a Desktop shortcut

The project folder has one installer file for each system. Each one needs [Node.js](https://nodejs.org) (the LTS version) and a connection to the internet for the first run.

- **macOS:** double-click `Install Corkboard.command` in the Finder.
- **Windows:** double-click `Install Corkboard.cmd`.

The installer gets the packages (`npm install`) when they are not there. It also gets the Electron program: new versions of npm do not run the install script of Electron, so `node_modules/electron/dist` can be absent after `npm install`. To get it by hand, run `node node_modules/electron/install.js`. Then it installs Corkboard as a desktop app and puts two shortcuts on the Desktop: **Corkboard** and **Update Corkboard**. The two sections below give the details for each system.

## Installed copy

`tools/deploy/install.sh` installs Corkboard as a desktop app (Electron) for daily use (`Install Corkboard.command` runs it):

- `~/Applications/Corkboard.app` is a small launcher. It loads the code from `~/Library/Application Support/Corkboard/app`, runs the server inside the app (port 4848), and shows Corkboard in its own window.
- The data is in `~/Library/Application Support/Corkboard/data`. The first install copies the dev data once. After that the two copies do not share data.
- Corkboard used to be called Pepe. The first `install.sh` run after the rename copies the old `~/Library/Application Support/Pepe` data (and window settings) into the Corkboard folder, keeps the old folder as a backup, and removes the old Pepe app and its Desktop shortcuts. Delete the old folder yourself once you are happy.
- The Desktop gets a **Corkboard** link to the app and an **Update Corkboard** shortcut.
- **Update Corkboard** copies the code from this folder into the installed app and tests it on port 4849. If the test passes, it replaces the code and restarts the app. If the test fails, nothing changes. Data is never touched. The log is in `logs/update.log`.
- An update never rebuilds the app. Run `install.sh` again only after a change to `electron/shell`, the app icon, or the Electron version.
- The icon is drawn in `electron/icon/icon.svg` (a corkboard with pinned notes and string). `bash tools/icon/make-icon.sh` turns it into `icon.png` and `Corkboard.icns`. `install.sh` puts that icon on the app and on the Update Corkboard shortcut.

The dev copy (port 4747) shows a red DEV tag. Electron and the packager are dev dependencies. The installed code does not include them.

```bash
bash tools/deploy/install.sh
```

A Claude Code guard (`~/.claude/hooks/pepe-guard.py` and deny rules in `~/.claude/settings.json`) keeps Claude away from the installed app, its data, its ports and these scripts. So the user runs `install.sh` and the updates, not Claude.

## Windows

Corkboard runs on Windows 10 and Windows 11. It needs [Node.js](https://nodejs.org) 20 or later.

To use it in the browser, do the steps of **Start** above in a terminal (PowerShell or Command Prompt). The commands are the same.

To install it as a desktop app, double-click `Install Corkboard.cmd` in the project folder. It runs `tools\deploy\install-windows.cmd`, which gets the packages when they are not there and then runs `node tools\deploy\windows.js install`.

The install does the same work as `install.sh` does on a Mac:

- The program goes to `%LOCALAPPDATA%\Programs\Corkboard\Corkboard.exe`.
- The code, the data and the logs go to `%APPDATA%\Corkboard` (folders `app`, `data` and `logs`). The first install copies the data of the project folder, when it has data.
- The Desktop gets **Corkboard** and **Update Corkboard**. The Start menu gets **Corkboard**.
- **Update Corkboard** copies the code from the project folder, tests it on a spare port, and then replaces the installed code. It stops the app for the change and starts it again. If the test fails, nothing changes. Data is never touched.
- Run the install again only after a change to `electron/shell`, the icon or the Electron version.

Differences on Windows:

- Use Ctrl where this text shows ⌘, and Alt where it shows ⌥. The app shows the Windows key names in its help and its tool tips.
- The menu bar of the window shows only while you hold Alt.
- `npx electron tools/icon/make-ico.js` makes `electron/icon/Corkboard.ico` from `icon.png`.

The Windows scripts were written on a Mac. Their copy, test and replace steps were run there in test folders. The parts that only Windows has (shortcuts, the stop and start of the app, the message windows) were not run on a Windows computer yet.

## Scripts

`tools/pdfwords.py` is a helper for scripts that make snippets and boards through the API of the server. It finds where words are in a PDF. It needs `pdftotext` (poppler).
